# Фикстуры ответов площадки

Ответы SourceCraft, снятые живьём 06.09.2026 и **обрезанные**, а не выдуманные: разбор
чужого API проверяется по тому, что сервер отдаёт на самом деле, — спека расходится
с ним систематически.

| Файл                                       | Что это                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `sourcecraft-merge-checks-success.json`    | `GET …/pulls/125/merge-checks` дословно                                  |
| `sourcecraft-merge-checks-processing.json` | тот же ответ со статусом `processing`/`in_progress`                      |
| `sourcecraft-merge-checks-failed.json`     | тот же ответ со статусом `failed`/`failure`                              |
| `sourcecraft-run-356-failed.json`          | `GET …/cicd/runs/356` — прогон с красным кубом `test`, кубы прорежены    |
| `sourcecraft-cube-log-350-oom.txt`         | хвост лога куба `test` прогона 350: OOM контейнера гейта, ANSI сохранён  |
| `sourcecraft-cube-log-356-failed-test.txt` | хвост лога куба `test` прогона 356: настоящий отказ теста, ANSI сохранён |

**Два файла merge-checks собраны из третьего заменой статусов.** Живого красного ответа
взять неоткуда: `merge-checks` отдаёт ПОСЛЕДНИЙ прогон каждого workflow, и после мерджа
он уже зелёный. Значения статусов при этом не выдуманы — они из энума `Run.Status`
OpenAPI-спеки площадки (`created`, `prepared`, `processing`, `success`, `failed`,
`canceled`, `timeout`, `skipped`, `awaiting_approval`, `rejected`); общий `status`
у `MergeChecks.Status` свой и короче — `in_progress`, `success`, `failure`.

**Живой КРАСНЫЙ ответ `merge-checks` снять пока неоткуда — снимите его при первом же
настоящем красном прогоне** и замените им оба собранных файла. Это ровно тот случай, про
который предупреждает `docs/platform/sourcecraft/api-gotchas.md` («спека врёт — прав
сервер»): значения статусов взяты из энума, но КАК сервер заполняет остальные поля
красного ответа, здесь пока предположение.

**ANSI в логах намеренно сохранён.** Куб отдаёт лог одной строкой с escape-последова­
тельностями, и очистка — часть разбора: без неё сессия лечения получает нечитаемый текст,
а поиск сигнатур отказа спотыкается о вставки посреди слов.
